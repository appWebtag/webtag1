# WebTag

Εφαρμογή στα ελληνικά για έναν επαγγελματία που διαχειρίζεται διαφημίσεις επιχειρήσεων στα social media.

## Τι περιλαμβάνει

- Επιχειρήσεις, στοιχεία επικοινωνίας, αναζήτηση και σημειώσεις.
- Προωθήσεις σε Facebook, Instagram, συνδυασμό των δύο, TikTok, LinkedIn ή άλλο κανάλι.
- Προγραμματισμένη έναρξη, πραγματική ημερομηνία δημοσίευσης, λήξη και ημερομηνία επόμενης ενέργειας.
- Επισκόπηση ενεργών διαφημίσεων, λήξεων εντός 7 ημερών, επόμενων ενεργειών και καθυστερήσεων.
- Μηνιαίο ημερολόγιο και λίστα εκκρεμοτήτων.
- Καρτέλα επιχείρησης με ενεργές, προγραμματισμένες και παλιότερες προωθήσεις.
- Ανανέωση με νέα εγγραφή που συνδέεται με την προηγούμενη. Οι παλιές εγγραφές παραμένουν.
- Σύνδεση ενός χρήστη μέσω Supabase Auth και ιδιωτικά δεδομένα μέσω Row Level Security.
- Προσαρμογή σε κινητό και υπολογιστή.

Πρόκειται για εργαλείο καταγραφής και προγραμματισμού. Δεν δημοσιεύει αυτόματα διαφημίσεις στα social media και δεν στέλνει email/SMS. Διαβάζει τα αποτελέσματα των πληρωμένων διαφημίσεων Meta (βλ. παρακάτω). Οι υπενθυμίσεις εμφανίζονται μέσα στην εφαρμογή.

## Παρούσα κατάσταση

Η εφαρμογή και το σχήμα της βάσης έχουν υλοποιηθεί και ελεγχθεί τοπικά. Δεν έχει δημιουργηθεί απομακρυσμένο repository, δεν έχει συνδεθεί πραγματικό Supabase project και δεν έχει γίνει δημοσίευση στη Vercel.

Η τοπική προεπισκόπηση χρησιμοποιεί πλασματικά στοιχεία. Στη δοκιμαστική λειτουργία οι αλλαγές μένουν μόνο στη μνήμη της σελίδας και χάνονται με ανανέωση. Η πραγματική λειτουργία χρησιμοποιεί αποκλειστικά το Supabase και δεν επιστρέφει σε δοκιμαστικά στοιχεία αν αποτύχει η σύνδεση.

## Γρήγορη δοκιμή στον υπολογιστή

Απαιτείται Node.js 24 LTS και npm. Άνοιξε τερματικό μέσα σε αυτόν τον φάκελο:

```powershell
npm ci
```

Για δοκιμαστική προβολή, δημιούργησε το αρχείο `.env.development.local` με αυτή τη γραμμή:

```dotenv
VITE_DEMO_MODE=true
```

Έπειτα:

```powershell
npm run dev
```

Άνοιξε `http://127.0.0.1:5173/`. Το αρχείο δοκιμαστικής ρύθμισης αγνοείται από το Git και δεν χρησιμοποιείται στο production build.

## Σύνδεση με Supabase

1. Δημιούργησε νέο Supabase project για την εφαρμογή.
2. Στο SQL Editor εκτέλεσε μία φορά ολόκληρο το `supabase/migrations/202609280001_initial.sql`. Το αρχείο προορίζεται για νέο project χωρίς ήδη υπάρχοντες πίνακες `businesses` και `promotions`. Είναι μία συναλλαγή: αν αποτύχει, δεν εφαρμόζεται μερικώς.
3. Από Authentication → Users δημιούργησε τον δικό σου χρήστη με email και κωδικό, επιβεβαιωμένο για σύνδεση. Η εφαρμογή χρησιμοποιεί email/password, χωρίς σύνδεσμο πρόσκλησης ή ροή δημιουργίας λογαριασμού.
4. Στις ρυθμίσεις Supabase Auth απενεργοποίησε το **Allow new users to sign up** και την ανώνυμη σύνδεση. Κράτησε ενεργή τη σύνδεση με email/password. Έτσι μόνο οι λογαριασμοί που δημιουργείς εσύ μπορούν να συνδεθούν.
5. Από τις ρυθμίσεις του project πάρε το Project URL και το **publishable key**. Δεκτό είναι επίσης το παλιότερο `anon` key. Το `service_role`/secret key δεν πρέπει ποτέ να μπει στην εφαρμογή, στο GitHub ή σε μεταβλητή `VITE_`.
6. Αντίγραψε το `.env.example` σε `.env.local`, συμπλήρωσε URL και publishable key και κράτησε `VITE_DEMO_MODE=false`. Αν υπάρχει `.env.development.local`, άλλαξε και εκεί το `VITE_DEMO_MODE=false`, γιατί έχει προτεραιότητα κατά την τοπική ανάπτυξη. Επανεκκίνησε την προεπισκόπηση μετά την αλλαγή.

Η βάση συνδέει κάθε εγγραφή με τον λογαριασμό σου. Οι σύνθετοι περιορισμοί της βάσης εμποδίζουν σύνδεση προώθησης με επιχείρηση άλλου χρήστη ή ανανέωση προώθησης άλλης επιχείρησης. Δεν παρέχεται μόνιμη διαγραφή από την εφαρμογή: η ακύρωση διατηρεί το ιστορικό.

## GitHub και Vercel

1. Δημιούργησε ιδιωτικό repository στο GitHub και ανέβασε τα περιεχόμενα αυτού του φακέλου. Συμπερίλαβε το `package-lock.json`, τη βάση `supabase/` και το `.env.example`. Το `.gitignore` εξαιρεί `node_modules`, `dist` και πραγματικά αρχεία `.env`.
2. Στη Vercel πρόσθεσε νέο project εισάγοντας αυτό το repository.
3. Χρησιμοποίησε framework **Vite**, εντολή build `npm run build`, output directory `dist` και Node.js 24.x. Οι βασικές ρυθμίσεις περιλαμβάνονται και στο `vercel.json`.
4. Στις Environment Variables της Vercel, για Production, βάλε:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
VITE_DEMO_MODE=false
```

5. Δημοσίευσε την εφαρμογή. Για preview deployments προτίμησε ξεχωριστό δοκιμαστικό Supabase project. Κάθε αλλαγή μεταβλητών `VITE_` απαιτεί νέο build/deployment.
6. Πρόσθεσε την τελική διεύθυνση στις ρυθμίσεις Site URL του Supabase Auth.
7. Συνδέσου, καταχώρισε μία δοκιμαστική επιχείρηση και προώθηση και κάνε ανανέωση της σελίδας. Επιβεβαίωσε ότι παραμένουν. Κάνε αποσύνδεση και βεβαιώσου ότι εμφανίζεται μόνο η οθόνη σύνδεσης.

Τα έργα και η φιλοξενία παραμένουν στους δικούς σου λογαριασμούς. Πριν τη δημοσίευση έλεγξε τα τρέχοντα πλάνα των υπηρεσιών για επαγγελματική χρήση· δεν έχουν αγοραστεί υπηρεσίες από αυτή την εργασία.

## Κατηγορίες, είδος και κόστος

- **Κατηγορίες:** στη θέση του τίτλου κάθε προώθηση έχει μία ή περισσότερες δικές σου κατηγορίες. Νέα κατηγορία φτιάχνεις μέσα στη φόρμα. Μετονομασία και διαγραφή γίνονται από «Προωθήσεις → Κατηγορίες». Οι παλιές προωθήσεις κρατούν τον τίτλο τους μέχρι να τους βάλεις κατηγορίες.
- **Είδος:** «Post» ή «Ads». Το post έχει μία ημερομηνία δημοσίευσης και καταχωρίζεται αμέσως ως ολοκληρωμένο. Το ads έχει έναρξη, λήξη και κατάσταση.
- **Κόστος διαφήμισης:** προαιρετικό ποσό σε €.
- **Φίλτρα στις Προωθήσεις:** είδος, κατηγορίες (όποια από τις επιλεγμένες), επιχείρηση, κανάλι και διάστημα ημερομηνιών (εμφανίζεται ό,τι η διάρκειά του πέφτει μέσα στο διάστημα). Μαζί εμφανίζεται και το σύνολο κόστους των αποτελεσμάτων.
- Βάση: `supabase/migrations/202609290003_categories_kind_cost.sql` (έχει ήδη εφαρμοστεί στο project `webtag`).

## Logo πελατών, σελίδα Meta και εξαγωγή PDF

- **Logo πελάτη:** στην επεξεργασία της επιχείρησης. Η εικόνα μετατρέπεται σε τετράγωνο PNG 256×256 και αποθηκεύεται στο **ιδιωτικό** bucket `business-logos` του Supabase Storage, στον φάκελο του χρήστη. Εμφανίζεται με προσωρινούς (υπογεγραμμένους) συνδέσμους.
- **Meta από την καρτέλα πελάτη:**
  - Διαλέγεις ποια σελίδα Facebook είναι του πελάτη. Οι διαφημίσεις αυτής της σελίδας που περιμένουν αντιστοίχιση πηγαίνουν στον πελάτη, και το ίδιο ισχύει για τις νέες σε κάθε συγχρονισμό.
  - Στο «Meta Ads» υπάρχει η λίστα «Σελίδες Facebook»: διαλέγεις πελάτη για κάθε σελίδα μία φορά και όλες οι καμπάνιες της (και οι νέες) πηγαίνουν αυτόματα σε αυτόν. Αν μεταφέρεις μια σελίδα σε άλλον πελάτη, μεταφέρονται και οι καμπάνιες της. Τα ονόματα των σελίδων έρχονται από τη Meta όταν το επιτρέπει το token· αλλιώς δίνεις εσύ όνομα με το μολύβι. Βάση: `supabase/migrations/202609300005_page_names.sql`.
  - Προσθέτεις ή αφαιρείς καμπάνιες του πελάτη.
  - Αντιστοιχίσεις που έχεις ήδη κάνει με το χέρι δεν αλλάζουν.
- **Εξαγωγή PDF:** στις Προωθήσεις, το κουμπί «Εξαγωγή PDF» βγάζει ό,τι εμφανίζεται με τα τρέχοντα φίλτρα. Η αναφορά είναι ομαδοποιημένη ανά πελάτη, με logo, κόστος και στατιστικά Meta. Η γραμματοσειρά DejaVu Sans (ελεύθερη άδεια, `public/fonts/LICENSE-DejaVu.txt`) περιλαμβάνεται για τα ελληνικά.
- **Ο λογαριασμός μου:** κάτω αριστερά (ή το εικονίδιο πάνω δεξιά) ανοίγουν τα στοιχεία σου: ονοματεπώνυμο, επωνυμία, τηλέφωνο, email, ιστοσελίδα, ΑΦΜ, διεύθυνση και logo. Το logo και η επωνυμία εμφανίζονται στο μενού και στην κεφαλίδα των αναφορών PDF. Βάση: `supabase/migrations/202609300002_profile.sql`.
- Βάση: `supabase/migrations/202609300001_logos_meta_pages.sql` (έχει ήδη εφαρμοστεί στο project `webtag`).

## Αποτελέσματα Meta (Facebook & Instagram)

Η εφαρμογή διαβάζει τα αποτελέσματα των **πληρωμένων διαφημίσεων** από έναν διαφημιστικό λογαριασμό Meta. Δεν δημιουργεί ούτε αλλάζει διαφημίσεις, προϋπολογισμούς ή δημοσιεύσεις.

- **Συγχρονισμός στον server:** η Edge Function `supabase/functions/meta-sync` τρέχει κάθε πρωί (pg_cron, 03:15 UTC) και όταν πατάς «Συγχρονισμός τώρα». Δουλεύει και με κλειστή την εφαρμογή.
- **Κλειδιά:** το token της Meta μπαίνει μόνο στα Secrets των Edge Functions (`META_ACCESS_TOKEN`, προαιρετικά `META_APP_SECRET`, `META_API_VERSION`). Δεν μπαίνει ποτέ στον κώδικα, στη Vercel ή στον browser. Το μυστικό του ημερήσιου προγραμματισμού το δημιουργεί η ίδια η βάση στο Vault.
- **Άδειες:** μόνο `ads_read`, μέσω system user του Business portfolio. Για τον δικό σου λογαριασμό αρκεί το βασικό επίπεδο πρόσβασης, χωρίς App Review.
- **Πολλοί διαφημιστικοί λογαριασμοί:** στο «Meta Ads → Σύνδεση» προσθέτεις όσους λογαριασμούς θέλεις. Συγχρονίζονται όλοι μαζί (αν αποτύχει ένας, οι άλλοι συνεχίζουν) και τα αποτελέσματα ενώνονται. Όταν μια προώθηση έχει διαφημίσεις σε περισσότερους λογαριασμούς, τα ποσά αθροίζονται, ενώ η απήχηση μένει κενή, γιατί δεν αθροίζεται. Με «Αποσύνδεση» ένας λογαριασμός σταματά να συγχρονίζεται και το ιστορικό του μένει. Βάση: `supabase/migrations/202609300003_multi_accounts.sql`.
- **Αντιστοίχιση:** οι νέες διαφημίσεις εμφανίζονται στο «Meta Ads → Νέες διαφημίσεις προς αντιστοίχιση». Εσύ επιλέγεις τον πελάτη· προτείνεται πελάτης μόνο όταν το όνομα της καμπάνιας ταιριάζει σε έναν και μοναδικό πελάτη.
- **Σύνδεση με προώθηση:** στην καρτέλα της προώθησης επιλέγεις καμπάνια ή διαφήμιση.
- **Χωρίς διπλομέτρηση:** μία εγγραφή ανά διαφήμιση και ημέρα (ενημερώνεται, δεν προστίθεται). Τα σύνολα κάθε προώθησης, και η απήχηση, ζητούνται από τη Meta για όλη την περίοδο με ένα ερώτημα, ώστε ο ίδιος χρήστης να μη μετρά δύο φορές.
- **Καθυστερημένα αποτελέσματα:** κάθε συγχρονισμός ξαναδιαβάζει τις τελευταίες 28 ημέρες. Τα σύνολα μιας προώθησης ενημερώνονται έως 28 ημέρες μετά τη λήξη της.
- **Νόμισμα και ζώνη ώρας:** χρησιμοποιούνται του διαφημιστικού λογαριασμού. Οι ημερομηνίες των ημερήσιων στοιχείων είναι στη ζώνη ώρας του λογαριασμού.
- **Κενό έναντι μηδενός:** «—» σημαίνει ότι η Meta δεν έδωσε τιμή· «0» είναι πραγματικό μηδέν. Μηνύματα, αιτήματα ενδιαφέροντος και αγορές εμφανίζονται μόνο όταν καταγράφονται ή όταν είναι ο στόχος της καμπάνιας.

Εγκατάσταση (έχει ήδη γίνει στο project `webtag`):

1. SQL Editor: `supabase/migrations/202609290001_meta.sql` και μετά `202609290002_meta_cron.sql` (άλλαξε το URL του project αν χρειάζεται).
2. Edge Functions: δημιουργία `meta-sync` με τον κώδικα του `supabase/functions/meta-sync/index.ts`, με **απενεργοποιημένο** το «Verify JWT with legacy secret». Η λειτουργία ελέγχει μόνη της τον συνδεδεμένο χρήστη ή το μυστικό του προγραμματισμού.
3. Secrets: `META_ACCESS_TOKEN` (και προαιρετικά `META_APP_SECRET`).

Έλεγχοι λειτουργίας συγχρονισμού (εκτός Supabase): `deno test -A supabase/functions/meta-sync/sync_test.ts`.

## Κανόνες ημερομηνιών και ιστορικού

- Όλες οι ημερομηνίες είναι ημερολογιακές ημερομηνίες, χωρίς ώρα. Η έννοια «σήμερα» χρησιμοποιεί Europe/Athens.
- Η ημέρα λήξης περιλαμβάνεται στη διάρκεια προβολής. Από την επόμενη ημέρα μια δημοσιευμένη προώθηση εμφανίζεται ως «Έληξε».
- Μια προγραμματισμένη προώθηση δεν χαρακτηρίζεται αυτόματα δημοσιευμένη. Αν περάσει η ημέρα της, παραμένει εκκρεμής.
- Η πραγματική ημερομηνία δημοσίευσης καταγράφεται ξεχωριστά από την αρχικά προγραμματισμένη έναρξη.
- Το κουμπί «Δημοσιεύτηκε» καταγράφει τη σημερινή ημερομηνία. Για άλλη πραγματική ημερομηνία χρησιμοποίησε την επεξεργασία.
- Η ολοκλήρωση δεν σβήνει τυχόν εκκρεμή ανανέωση. Η καταχώριση της επόμενης προώθησης καλύπτει αυτή την εκκρεμότητα.
- Η ακύρωση μιας ανανέωσης επαναφέρει την εκκρεμότητα της προηγούμενης, εφόσον είχε ημερομηνία επόμενης ενέργειας.
- Η ακύρωση μιας προώθησης δεν ακυρώνει αυτόματα επόμενες προωθήσεις που έχουν καταχωριστεί ξεχωριστά.
