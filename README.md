# Promo Desk

Εφαρμογή στα ελληνικά για έναν επαγγελματία που διαχειρίζεται διαφημίσεις επιχειρήσεων στα social media.

## Τι περιλαμβάνει

- Επιχειρήσεις, στοιχεία επικοινωνίας, αναζήτηση και σημειώσεις.
- Προωθήσεις σε Facebook, Instagram, συνδυασμό των δύο, TikTok, LinkedIn ή άλλο κανάλι.
- Προγραμματισμένη έναρξη, πραγματική ημερομηνία δημοσίευσης, λήξη και ημερομηνία επόμενης ενέργειας.
- Επισκόπηση ενεργών διαφημίσεων, λήξεων εντός 7 ημερών, επόμενων ενεργειών και καθυστερήσεων.
- Μηνιαίο ημερολόγιο και λίστα εκκρεμοτήτων.
- Καρτέλα επιχείρησης με ενεργές, προγραμματισμένες και παλιότερες προωθήσεις.
- Ανανέωση με νέα εγγραφή που συνδέεται με την προηγούμενη. Οι παλιές εγγραφές παραμένουν.
- Σύνδεση ενός χρήστη μέσω Supabase Auth και ιδιωτικά δεδομένα μέσω Row Level Security.
- Προσαρμογή σε κινητό και υπολογιστή.

Πρόκειται για εργαλείο καταγραφής και προγραμματισμού. Δεν δημοσιεύει αυτόματα διαφημίσεις στα social media και δεν στέλνει email/SMS. Οι υπενθυμίσεις εμφανίζονται μέσα στην εφαρμογή.

## Παρούσα κατάσταση

Η εφαρμογή και το σχήμα της βάσης έχουν υλοποιηθεί και ελεγχθεί τοπικά. Δεν έχει δημιουργηθεί απομακρυσμένο repository, δεν έχει συνδεθεί πραγματικό Supabase project και δεν έχει γίνει δημοσίευση στη Vercel.

Η τοπική προεπισκόπηση χρησιμοποιεί πλασματικά στοιχεία. Στη δοκιμαστική λειτουργία οι αλλαγές μένουν μόνο στη μνήμη της σελίδας και χάνονται με ανανέωση. Η πραγματική λειτουργία χρησιμοποιεί αποκλειστικά το Supabase και δεν επιστρέφει σε δοκιμαστικά στοιχεία αν αποτύχει η σύνδεση.

## Γρήγορη δοκιμή στον υπολογιστή

Απαιτείται Node.js 24 LTS και npm. Άνοιξε τερματικό μέσα σε αυτόν τον φάκελο:

```powershell
npm ci
```

Για δοκιμαστική προβολή, δημιούργησε το αρχείο `.env.development.local` με αυτή τη γραμμή:

```dotenv
VITE_DEMO_MODE=true
```

Έπειτα:

```powershell
npm run dev
```

Άνοιξε `http://127.0.0.1:5173/`. Το αρχείο δοκιμαστικής ρύθμισης αγνοείται από το Git και δεν χρησιμοποιείται στο production build.

## Σύνδεση με Supabase

1. Δημιούργησε νέο Supabase project για την εφαρμογή.
2. Στο SQL Editor εκτέλεσε μία φορά ολόκληρο το `supabase/migrations/202609280001_initial.sql`. Το αρχείο προορίζεται για νέο project χωρίς ήδη υπάρχοντες πίνακες `businesses` και `promotions`. Είναι μία συναλλαγή: αν αποτύχει, δεν εφαρμόζεται μερικώς.
3. Από Authentication → Users δημιούργησε τον δικό σου χρήστη με email και κωδικό, επιβεβαιωμένο για σύνδεση. Η εφαρμογή χρησιμοποιεί email/password, χωρίς σύνδεσμο πρόσκλησης ή ροή δημιουργίας λογαριασμού.
4. Στις ρυθμίσεις Supabase Auth απενεργοποίησε το **Allow new users to sign up** και την ανώνυμη σύνδεση. Κράτησε ενεργή τη σύνδεση με email/password. Έτσι μόνο οι λογαριασμοί που δημιουργείς εσύ μπορούν να συνδεθούν.
5. Από τις ρυθμίσεις του project πάρε το Project URL και το **publishable key**. Δεκτό είναι επίσης το παλιότερο `anon` key. Το `service_role`/secret key δεν πρέπει ποτέ να μπει στην εφαρμογή, στο GitHub ή σε μεταβλητή `VITE_`.
6. Αντίγραψε το `.env.example` σε `.env.local`, συμπλήρωσε URL και publishable key και κράτησε `VITE_DEMO_MODE=false`. Αν υπάρχει `.env.development.local`, άλλαξε και εκεί το `VITE_DEMO_MODE=false`, γιατί έχει προτεραιότητα κατά την τοπική ανάπτυξη. Επανεκκίνησε την προεπισκόπηση μετά την αλλαγή.

Η βάση συνδέει κάθε εγγραφή με τον λογαριασμό σου. Οι σύνθετοι περιορισμοί της βάσης εμποδίζουν σύνδεση προώθησης με επιχείρηση άλλου χρήστη ή ανανέωση προώθησης άλλης επιχείρησης. Δεν παρέχεται μόνιμη διαγραφή από την εφαρμογή: η ακύρωση διατηρεί το ιστορικό.

## GitHub και Vercel

1. Δημιούργησε ιδιωτικό repository στο GitHub και ανέβασε τα περιεχόμενα αυτού του φακέλου. Συμπερίλαβε το `package-lock.json`, τη βάση `supabase/` και το `.env.example`. Το `.gitignore` εξαιρεί `node_modules`, `dist` και πραγματικά αρχεία `.env`.
2. Στη Vercel πρόσθεσε νέο project εισάγοντας αυτό το repository.
3. Χρησιμοποίησε framework **Vite**, εντολή build `npm run build`, output directory `dist` και Node.js 24.x. Οι βασικές ρυθμίσεις περιλαμβάνονται και στο `vercel.json`.
4. Στις Environment Variables της Vercel, για Production, βάλε:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
VITE_DEMO_MODE=false
```

5. Δημοσίευσε την εφαρμογή. Για preview deployments προτίμησε ξεχωριστό δοκιμαστικό Supabase project. Κάθε αλλαγή μεταβλητών `VITE_` απαιτεί νέο build/deployment.
6. Πρόσθεσε την τελική διεύθυνση στις ρυθμίσεις Site URL του Supabase Auth.
7. Συνδέσου, καταχώρισε μία δοκιμαστική επιχείρηση και προώθηση και κάνε ανανέωση της σελίδας. Επιβεβαίωσε ότι παραμένουν. Κάνε αποσύνδεση και βεβαιώσου ότι εμφανίζεται μόνο η οθόνη σύνδεσης.

Τα έργα και η φιλοξενία παραμένουν στους δικούς σου λογαριασμούς. Πριν τη δημοσίευση έλεγξε τα τρέχοντα πλάνα των υπηρεσιών για επαγγελματική χρήση· δεν έχουν αγοραστεί υπηρεσίες από αυτή την εργασία.

## Κανόνες ημερομηνιών και ιστορικού

- Όλες οι ημερομηνίες είναι ημερολογιακές ημερομηνίες, χωρίς ώρα. Η έννοια «σήμερα» χρησιμοποιεί Europe/Athens.
- Η ημέρα λήξης περιλαμβάνεται στη διάρκεια προβολής. Από την επόμενη ημέρα μια δημοσιευμένη προώθηση εμφανίζεται ως «Έληξε».
- Μια προγραμματισμένη προώθηση δεν χαρακτηρίζεται αυτόματα δημοσιευμένη. Αν περάσει η ημέρα της, παραμένει εκκρεμής.
- Η πραγματική ημερομηνία δημοσίευσης καταγράφεται ξεχωριστά από την αρχικά προγραμματισμένη έναρξη.
- Το κουμπί «Δημοσιεύτηκε» καταγράφει τη σημερινή ημερομηνία. Για άλλη πραγματική ημερομηνία χρησιμοποίησε την επεξεργασία.
- Η ολοκλήρωση δεν σβήνει τυχόν εκκρεμή ανανέωση. Η καταχώριση της επόμενης προώθησης καλύπτει αυτή την εκκρεμότητα.
- Η ακύρωση μιας ανανέωσης επαναφέρει την εκκρεμότητα της προηγούμενης, εφόσον είχε ημερομηνία επόμενης ενέργειας.
- Η ακύρωση μιας προώθησης δεν ακυρώνει αυτόματα επόμενες προωθήσεις που έχουν καταχωριστεί ξεχωριστά.

## Έλεγχοι

```powershell
npm test
npm run build
```

Οι αυτοματοποιημένοι έλεγχοι καλύπτουν λήξεις, αλλαγή ημέρας στην Ελλάδα, αλλαγές θερινής ώρας, εκκρεμείς δημοσιεύσεις, ανανεώσεις, διατήρηση ιστορικού, μη έγκυρες ημερομηνίες και ελληνική αναζήτηση.

Το SQL ελέγχθηκε επιπλέον σε απομονωμένη PostgreSQL μέσω PGlite, με προσομοιωμένη την υπηρεσία ταυτοποίησης: 43 έλεγχοι πρόσβασης και περιορισμών πέρασαν. Αυτό δεν αντικαθιστά τον τελικό έλεγχο σύνδεσης και αποθήκευσης στο πραγματικό Supabase project.
